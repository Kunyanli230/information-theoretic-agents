# VoI-Delegate — 方法与结果

> 仅起草章节。验证性分析样本量不足（**underpowered**，7 个任务）。主张边界遵循 `CLAIMS_BOUNDARY.md`（2026-10-14）。

---

## 方法

### 模型与任务

执行器为冻结的小规模代码模型 `Qwen2.5-Coder-0.5B-Instruct`（Hugging Face 快照 `ea3f2471cf1b1f0db85067f1ef93848e38e88c25`），在 CPU 上以 fp32 运行，采样温度 0.7，`top_p=0.95`，`max_new_tokens=256`。每次尝试的随机种子固定，使得相同种子产生字节级相同的改写。每个回合最多 \(K=4\) 次改写尝试，可见单元测试通过时提前停止；终局成功要求最终代码通过隐藏测试。

指导模型通过 Cursor Agent CLI 版本 `2026.10.01-e373342` 调用，固定无头命令为

```text
agent -p --mode=ask --model grok-4.6 --output-format text --workspace <empty-temp-dir> "<prompt>"
```

`--mode=ask` 使指导端只读。指导端返回单一结构化 JSON 诊断，字段为 `location`、`cause`、`change`、`verification` 与 `applicable_if`（锚定请求快照的精确代码子串）。路径 A 对每个校准或验证前缀使用新鲜的 `grok-4.6` 诊断；Codex CLI 已卸载，未用于这些运行。

任务为合成的单函数 Python 修错题。我们复用试点中经难度过滤保留的十五个任务（`T09`、`T10`、`T11`、`T12`、`T14`、`T17`、`T20`、`T26`、`T28`、`T31`、`T32`、`T33`、`T37`、`T38`、`T40`）。在校准结果用于编码器或门控拟合之前，任务池已固定划分为八个校准任务（所列 `T09`–`T26`）与七个验证任务（`T28`、`T31`、`T32`、`T33`、`T37`、`T38`、`T40`）。仅有七个验证任务时，所有验证效力与消融对比均标注为**样本量不足（underpowered）**。

在相同 Cursor CLI / `grok-4.6` 指导下，能力差距预检要求指导单独成功率减去冻结小模型单独成功率至少 15 个百分点（pp），验证路径方可继续。

### 协议

在每次可见尝试失败后的决策边界 \(j\in\{1,2,3\}\)，若无在途请求且仍有剩余尝试，调度器用执行校准的预测干预增益 \(\widehat\Delta\)（在冻结的此后不再调用指导的策略 \(\pi_0\) 下延续）对候选方案 \(q\in\{0\}\cup\mathcal{Q}\) 打分。仅当 \(\mathrm{score}(q^\star)>0\) 且可预留费用时才支付指导调用；支付前不观察诊断 \(z\) 与消息 \(m\)。任意时刻至多一个在途指导请求。

消息携带 `applicable_if`。投递时，实验框架对照当前代码检查该谓词；失败则将消息丢弃为**过期（stale）**。在穿越延迟的臂上施加注入投递延迟 \(d\in\{0,1,2\}\)（请求后的执行器尝试数），用于机制与长度–延迟描述。若可见测试在投递前已通过，则将该消息记为不需要。

有限结构化消息族为

| id | 字段 |
|---|---|
| \(m_1\) | 定位 |
| \(m_2\) | 定位 + 原因 |
| \(m_3\) | 定位 + 原因 + 修改/步骤 |
| \(m_4\) | 定位 + 原因 + 修改 + 验证 |

所有模板均携带 `applicable_if`。嵌套校准保留集随后冻结默认编码族：**短** \(=m_2\)，**长** \(=m_3\)，并**去掉 \(m_4\)**（与 \(m_3\) 校准成功率相同，但编码后消息成本更高）。

### 校准

在 \(N=24\) 个可恢复前缀上（八个校准任务 × 三个第 1 次尝试失败快照），每个前缀共享一次新鲜诊断 \(z\)。分叉包括对照（无指导）、\(m_1\)–\(m_4\) 在延迟 \(d\in\{0,1,2\}\) 下各一组，以及一次接管参考，在共同随机数（CRN）延续下共 336 个分叉，每方案重复 \(S=1\)。决策失真遵循预注册定义 \(d_h(z,m)=v_h^\star(z)-v_h(z,m)\)。编码器成本 \(\widehat c_h(z,m)\) 为渲染消息的**编码后**估计 token 成本；诊断输出 token 为共享基线，仅记录一次，不单独区分模板。

### 编码器

在有限表上离线进行定理 1 风格的 Blahut–Arimoto 拟合，由校准分叉估计编码器 \(e^\star\)。八个校准任务内的嵌套保留集以 `T09`–`T17`（六个任务）为拟合集、`T20`、`T26` 为保留集。保留集选择无 \(m_4\) 族与超参数 \((\lambda,\beta)=(0.0,0.05)\)。在 \(\lambda=0\) 时，冻结 argmax 策略集中于固定长消息 \(m_3\)（22/24 前缀），因此率失真编码器存在坍缩为“带符号门控 + 固定长指导”的风险；验证评估因此显式消融该对比。按延迟的离散 argmax 表存档用于定理 2 诊断，但不视为有功效的长度–延迟检验。

在相同校准分叉上拟合 \(\widehat\Delta\) 的表格增益预测器，嵌套保留集选择门控惩罚 \(\lambda=0.001\)、\(\mu=0.0\)。

### 验证评估

验证评估使用七个留出任务 × 三个快照（21 个前缀；378 个回合），编码器与门控产物冻结，并使用路径 A 新鲜诊断。臂设置为：

| 臂 | 时机 | 消息 / 方案 | 角色 |
|---|---|---|---|
| **C0** | — | 无指导 | 下界 |
| **C1** | 第 1 次尝试失败后固定 | 完整修正代码（接管） | 中途升级参考 |
| **C2** | 第 1 次尝试失败后固定 | 短 \(m_2\) | 固定短 |
| **C3** | 第 1 次尝试失败后固定 | 长 \(m_3\) | 固定长；与 C2 构成长度×延迟 |
| **G_fix** | VoI 门控；\(q\in\{0,q_{\mathrm{short}}\}\) | 固定短 | 消融 |
| **G_fixL** | VoI 门控；\(q\in\{0,q_{\mathrm{long}}\}\) | 固定长 | 消融 |
| **VD_enc** | VoI 门控；候选 \(\{\mathrm{none},\mathrm{short},\mathrm{long},\mathrm{rd}\}\) | 定理 1 的 \(e^\star\)（无接管） | Q3 编码器对比 |
| **VD** | VoI 门控；候选含接管 | 含升级的完整方法 | 随接管率一并报告 |

在消息臂与门控请求臂上施加延迟 \(d\in\{0,1,2\}\)。臂 **VD_enc** 在看到验证结果之前加入，专门使 Q3 编码器对比不被升级路由混淆。

### 指标

主要效力指标为终局隐藏测试成功。主要成本计量为指导调用次数、编码后消息侧成本 \(c_h(z,m)\)，以及可用的指导 token 或字符字段；面向该指导路径的正式总 token 20%/10% 成本节约门控**未**恢复。记录消息处置（接受 / 过期 / 不需要）以及延迟投递（\(d\ge 1\)）上的过期丢弃率。对门控臂始终报告已支付请求中的接管选择率。

预注册的主要分析包括比较 C3 与 C2 的 Q2 logistic 回归 `success ~ arm * delay + task_FE`。本稿**未运行**该 logistic；下文长度–延迟结果仅为描述性比率。Q3 使用 **VD_enc** 相对 **G_fixL** 的成对成功差。结果文件中已有的 Wilson 90% 区间一并报告。所有验证对比仍为样本量不足。

## 结果

### 能力差距预检

在 Cursor CLI / `grok-4.6` 下，指导单独成功率为 **100%**（15/15 保留任务），冻结小模型单独为 **56%**，差距 **44.0 pp**，通过 ≥15 pp 规则。验证路径因此继续（非探索性降级）。

### 校准成功率

在延迟上汇总后，\(N=24\) 前缀上的校准成功率为：对照 **41.7%**（10/24），\(m_1\) **43.1%**（31/72），\(m_2\) **52.8%**（38/72），\(m_3\) **77.8%**（56/72），\(m_4\) **77.8%**（56/72），接管 **91.7%**（22/24）。因 \(m_1\) 接近对照，短类设为 \(m_2\)。因 \(m_3\) 与 \(m_4\) 成功率相同而 \(m_4\) 消息成本更高（估计 token 78.8 对 110.9），默认编码族去掉 \(m_4\)。

按延迟，长模板比率呈方向性下降（\(m_3\)：在 \(d=0,1,2\) 为 83.3% / 79.2% / 70.8%）；短 \(m_2\) 为 58.3% / 54.2% / 45.8%。状态计数中，延迟分叉含 16 次过期投递（约占校准延迟投递的 8%）——保留为适用性机制的校准观察。

### 离线编码器

嵌套保留集选择族 \(m_1\)–\(m_3\)（无 \(m_4\)）与 \((\lambda,\beta)=(0.0,0.05)\)。冻结 argmax 计数为 \(\{m_1:0,\,m_2:2,\,m_3:22\}\)；校准上（汇总）argmax 策略成功率为 0.806、消息成本 76.1，接近固定 \(m_3\)（0.778 / 78.8）。按延迟条件的 argmax **未**随 \(d\) 增大而将质量移向更短消息（\(d=0\)：2×\(m_2\)+22×\(m_3\)；\(d=1\)–\(2\)：24×\(m_3\)）。这些校准事实预示编码器增量偏弱，并不构成有功效的定理 2 检验。

### 验证臂成功率（样本量不足）

在七个验证任务上（21 个快照；适用处对延迟汇总）：

| 臂 | 比率 | \(k/n\) | 90% Wilson |
|-----|------|---------|------------|
| C0 | 38.1% | 8/21 | [0.23, 0.56] |
| C1 | 95.2% | 20/21 | [0.81, 0.99] |
| C2 | 55.6% | 35/63 | [0.45, 0.65] |
| C3 | 81.0% | 51/63 | [0.72, 0.88] |
| G_fix | 58.7% | 37/63 | [0.48, 0.68] |
| G_fixL | 81.0% | 51/63 | [0.72, 0.88] |
| VD_enc | 84.1% | 53/63 | [0.75, 0.90] |
| VD（完整） | 95.2% | 20/21 | [0.81, 0.99] |

**长指导有帮助。**固定长 C3 与门控固定长 G_fixL 均达到 **≈81.0%**，明显高于对照 C0 **38.1%** 与短 C2 **≈55.6%**。短门控 G_fix（58.7%）接近 C2。

### 编码器增量（Q3）：仅 VD_enc

Q3 编码器对比仅使用 **VD_enc** 对 G_fixL：**84.1%** 对 **81.0%**，成对均值差 **+3.2 pp**（63 对）。经验增量存在但很小、样本量不足，且**仅为方向性**；**不是**有功效的主要贡献。因此在本玩具任务池上，定理 1 的经验支持仍然偏弱。

完整 **VD** 亦达到 **95.2%**（20/21），但 `takeover_among_paid=1.0`（21/21 已支付请求选择接管）。该臂因此坍缩为升级路由，与 C1 一致，**不**作为指导或编码器证据。G_fix、G_fixL 与 VD_enc 各自 `takeover_among_paid=0`（已支付方案分别为短、长与 `rd`）。

### 长度 × 延迟（描述性；未运行 logistic）

描述性 C3×延迟比率为 \(d=0,1,2\) 时 **85.7% / 71.4% / 85.7%**（非单调）。C2×延迟比率为 52.4% / 61.9% / 52.4%。我们**不**根据这些比率或校准离散 argmax 声称“最优长度随延迟变短”，也不声称有功效的定理 2 结果。预注册的验证 logistic 交互项未在本稿中计算。

### 过期丢弃

在验证的延迟投递上，过期率为 **4.76%**（10/210），低于 5% 阈值。适用性 / 过期机制仍保留在协议中，并报告为**工程细节**，而非头条贡献。校准过期计数（延迟分叉中 16 次）仅作为上文校准观察。

### 成本计量

门控验证臂上的指导调用行为，在上文报告的已支付请求层面一致（拟合门控下每个门控臂在 21 个前缀上 21 次已支付请求）。验证摘要中可用的平均指导输出估计为：C0 为 0，C1 与完整 VD（接管路径）约 33.5，C2、C3、G_fix、G_fixL 与 VD_enc 约 123.2。消息侧校准成本仍为编码器拟合中的数值（\(m_2\) 约 50.1、\(m_3\) 约 78.8 估计 token）。不提出总 token 成本节约门控或阈值主张；该门控在 Grok 时代计量下未恢复。
